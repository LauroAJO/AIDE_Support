9. INTELLIGENCE HUB
================================

Endpoints que o Hub (IntelligenceHub, projeto externo em
X:\_Software\Projetos Pessoais\IntelligenceHub) usa para se comunicar com o
AIDE:
  - POST /api/hub/items                    — envia itens coletados/classificados
    (autenticado por API key, header Authorization: ApiKey <HUB_API_KEY>,
    não usa sessão de usuário). Body: { items: [{ external_id, project_id,
    title, url, source_name, published_at, relevancia, prioridade, tipo,
    resumo, topicos, justificativa, collected_at, country }, ...] }.
    Idempotente via UNIQUE(external_id, project_id) + ON CONFLICT DO UPDATE;
    nunca reativa um item com deleted_at preenchido.
  - GET /api/hub/excluded-ids?project_id=... — consultado pelo IntelligenceHub
    (visto nos logs como "aide_exporter") ANTES de cada envio, para saber
    quais external_ids já foram deletados/arquivados no AIDE e não devem ser
    reingeridos. Requer sessão de usuário do AIDE (não API key) — ver nota
    abaixo sobre falhas 401 observadas nos logs do Hub.

Categorização/filtro na UI:
  - project_id é uma coluna TEXT livre (não há tabela hub_projects) — valores
    observados em produção: h2, energia, ia, phd_vagas, emprego_vagas.
  - h2/energia/ia caem na subaba "Notícias" (HubPage.jsx) por padrão; vagas
    (phd_vagas, emprego_vagas) só aparecem quando explicitamente pedidas por
    ?project=, cada uma com subaba própria (VagasPhDPage / EmpregoPage) e
    lógica de categorização adicional client-side (país + área temática por
    keyword matching, com overrides manuais).
  - Um dashboard "visão geral" (HubContainer) mostra 1 card por projeto
    (contagem + data do último item) e permite navegar diretamente para a
    subaba/filtro correspondente.
  - relevancia/prioridade vêm prontas do LLM do Hub; badges coloridos no
    front (verde=alta, âmbar=media, cinza=baixa).

Contagem por projeto (D1 remoto, produção — consistente com a query da
seção 2, total geral 1467):
  phd_vagas:      510 total | 41 ativos (visíveis)
  h2:             460 total | 460 ativos
  emprego_vagas:  192 total | 34 ativos
  ia:             165 total | 165 ativos
  energia:        140 total | 140 ativos
  (h2/ia/energia têm 100% dos itens ativos — nenhum deletado/arquivado ainda;
  phd_vagas e emprego_vagas têm alta taxa de itens inativos, consistente com
  vagas expiradas/removidas ou migradas para Carreira via archived_at +
  hub_short_id)

Filtro, busca e paginação em HubPage.jsx:
  - Filtro de projeto (select: Todos/H₂/Energia/IA) — controlado pelo
    HubContainer pai (para permitir pré-seleção via clique no dashboard).
  - Filtro de relevância mínima (1 a 5) — enviado ao backend
    (?min_relevancia=).
  - Busca textual (título/resumo) — 100% client-side (filtra o array já
    carregado, não faz nova request).
  - "Paginação": não há paginação real na UI — a página sempre pede
    limit=200 de uma vez (order_by=received_at DESC) e não há botão de
    "carregar mais"/scroll infinito. O backend (handleHubItems) SUPORTA
    limit/offset (?limit=, ?offset=, até 200 por página), mas o frontend
    não usa offset — se um projeto tiver mais de 200 itens ativos, os itens
    além do 200º não aparecem na UI atualmente. Nenhum dos projetos ativos
    (máx. 460 em h2) excede visivelmente esse limite hoje pela contagem de
    "ativos", mas vale monitorar caso o volume cresça.

ACHADO IMPORTANTE (relacionado ao Hub, para revisão antes de novas
mudanças): os logs mais recentes do IntelligenceHub (logs/hub.log, runs
#106–#109, 26–29/jul/2026) mostram falha recorrente de 401 Unauthorized ao
chamar GET /api/hub/excluded-ids para os 5 projetos, em TODOS os runs
recentes:
  "AIDE excluded-ids: falha ao consultar projeto <X> (401 Client Error:
  Unauthorized for url: https://aide-support.pages.dev/api/hub/excluded-ids
  ?project_id=<X>). Continuando sem filtrar por essa fonte neste run."
Isso é coerente com o código: handleHubExcludedIds exige sessão de usuário
válida (isHubReader), não a HUB_API_KEY usada pela ingestão — se o
IntelligenceHub estiver usando a mesma API key para os dois endpoints (ou um
token de sessão expirado), a chamada a excluded-ids sempre falhará com 401.
O hub continua funcionando (a ingestão via API key não é afetada), mas o
mecanismo de "não reingerir itens deletados/arquivados" está inoperante há
pelo menos 4 execuções diárias consecutivas — pode causar reativação
indevida de itens ou apenas silenciosamente listar excluded_ids: [] sempre
(que é o efeito prático hoje). Recomenda-se decidir entre (a) o
IntelligenceHub passar a autenticar excluded-ids com uma sessão/token válido
de usuário AIDE, ou (b) mudar handleHubExcludedIds para aceitar também a
HUB_API_KEY, já que é uma leitura de suporte à mesma pipeline de ingestão.
